## Severity scale (Nielsen's 0 to 4)

The plan and Assignment 1 use Nielsen's 0 to 4 scale; the definitions below are Nielsen's own. Row 0 is kept because the scale starts there. If the team decides to rate from 1 to 4 only, delete row 0 and say so in the report. Every issue rated **3 or 4** must be fixed and retested before MS4 (Sun 29 November 2026).

| Rating | Meaning | What to do |
|---|---|---|
| 0 | Not a usability problem. Recorded, not counted. | None. |
| 1 | Cosmetic. Fix if time allows. | Log only. |
| 2 | Minor. Low priority. | Log; fix after 3 and 4. |
| 3 | Major. Important to fix; participants struggle or are misled. | Fix before MS4 and retest. |
| 4 | Usability catastrophe. Participants cannot finish, or are misled about what a flag means. | Fix before MS4 and retest. Treat as blocking. |

Record each issue in `findings-template.md` with the severity you chose and the session and task where it was seen.
